# Guardrail Framework Comparison

Provider offerings and pricing change; verify current terms before procurement. “Model-agnostic” means the guardrail can screen traffic for different target models, not that every detector runs without its own model or service.

| Framework / provider | License or cost | Model dependence | PII masking | Other security coverage and banking fit |
|---|---|---|---|---|
| [NeMo Guardrails](https://github.com/NVIDIA-NeMo/Guardrails), NVIDIA | Open source, Apache 2.0; hosting and external model costs are separate. | Supports multiple LLM providers; some screening integrations use separate models/services. | Configurable detection and masking rails. Review detector dependencies (for example, Presidio/GLiNER) and deployment. | Input, output, retrieval, dialog, and tool rails; topic, jailbreak, moderation, hallucination, and custom flows. Strong open-source candidate; validate fail-closed behavior and Gemini/LangGraph integration. |

Good developer framework, not a complete agent-security platform; PII masking uses Presidio underneath. |

Strong if AWS is acceptable; review cost and data boundary. |

## Shortlist

- **Open-source framework:** NeMo Guardrails. It offers broad rails including PII masking, but verify the detector dependencies, integration, and fail-closed behavior.
- **Managed sanitize-and-screen candidate:** Pangea AI Guard. Ask about private deployment, data retention, regional processing, audit evidence, and production pricing.
- **Additional managed candidates:** Check Point AI Guardrails and Google Model Armor. Confirm that their configured PII action redacts before data reaches the model.

These frameworks do not replace backend account authorization, MFA, transfer validation, idempotency, or audit logging.
